1. Ringkasan Alur Integrasi

Seluruh endpoint H2H dipasang langsung pada prefix /h2h/* menggunakan format request dan respons JSON dengan batas ukuran payload 100 KB.

  1. Buat API Key di Dashboard → Integrasi H2H, lalu simpan API Key dan Webhook Secret yang hanya ditampilkan sekali.
  2. Daftarkan Allowed IP (IP publik server atau rentang CIDR Anda) untuk mengunci akses API Key.
  3. Sinkronkan produk secara berkala lewat GET /h2h/products untuk mendapatkan productId dan harga modal akun Anda.
  4. Kirim transaksi via POST /h2h/order dengan menyertakan ref_id unik agar percobaan ulang aman (idempoten).
  5. Terima pembaruan final secara real-time melalui Webhook Callback bertanda tangan HMAC-SHA256 atau polling GET /h2h/order/:refOrInvoiceId.

2. Autentikasi, Allowed IP & Batas Request

Setiap permintaan ke endpoint /h2h/* wajib lolos pemeriksaan IP Allowlist (jika diisi) dan autentikasi API Key.

  • Header Wajib: X-API-Key: <API_KEY_ANDA> (kunci acak 64 karakter hex / 32 byte; kunci lama 48 karakter hex tetap didukung selama masa transisi).
  • Header Body JSON: Sertakan Content-Type: application/json untuk permintaan POST dan PUT.
  • Allowed IP: Maksimal 20 entri IPv4/IPv6 tunggal atau rentang CIDR (mis. 203.0.113.10 atau 203.0.113.0/24). Jika terisi minimal 1 IP, akses dari IP lain ditolak dengan HTTP 403.
  • Rate Limit: Maksimal 60 request/menit per API Key dan per user pada grup /h2h/* (serta batas umum 300 request/5 menit per IP). Batas kuota transaksi atau nominal harian H2H juga dapat berlaku sesuai kebijakan sistem pusat.
Jangan pernah meletakkan X-API-Key atau Webhook Secret pada kode frontend, repositori publik, atau parameter query URL.

POST /h2h/order

Membuat transaksi pembelian top up secara atomik memakai saldo akun Anda. Gunakan ref_id unik per pesanan agar percobaan ulang (retry) ketika jaringan bermasalah tidak menimbulkan pemotongan saldo ganda.

Parameter Request Body (JSON)

Field Tipe Wajib Keterangan
productId number Ya ID numerik produk dari GET /h2h/products (bilangan bulat positif).
targetGameId string Ya User ID akun game tujuan (maks. 80 karakter).
targetServerId string Kondisional Zone / Server ID tujuan (maks. 80 karakter; wajib jika game memerlukan Server ID).
ref_id string Sangat disarankan ID referensi unik sistem Anda untuk idempotency: 1–100 karakter pola ^[A-Za-z0-9._:-]{1,100}$.
Aturan Idempotency: Jika ref_id dikirim ulang dengan productId, targetGameId, dan targetServerId yang identik, server membalas HTTP 200 + "idempotent": true tanpa transaksi baru. Jika payload berbeda dengan ref_id sama, server menolak dengan HTTP 409. Tanpa ref_id, order identik dalam 15 detik selama status masih Pending ditolak dengan HTTP 400. Jika koneksi ke upstream timeout, transaksi tetap berstatus Pending (HTTP 201) untuk rekonsiliasi otomatis.
Contoh cURL 
curl -X POST "https://domain-toko-anda.com/h2h/order" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: <API_KEY_ANDA>" \
  -d '{
    "productId": 12,
    "targetGameId": "12345678",
    "targetServerId": "2001",
    "ref_id": "ORD-20261124-001"
  }'
Respons 201 Created 
{
  "success": true,
  "message": "Pesanan H2H Anda sedang diproses!",
  "data": {
    "invoiceId": "H2H-1732450123-AB12",
    "status": "Pending",
    "productName": "86 Diamonds",
    "target": "12345678|2001",
    "price": 19500
  }
}
Respons 200 OK (Retry Idempotent) 
{
  "success": true,
  "idempotent": true,
  "message": "Transaksi H2H sudah tercatat sebelumnya (idempotent).",
  "data": {
    "invoiceId": "H2H-1732450123-AB12",
    "status": "Pending",
    "productName": "86 Diamonds",
    "target": "12345678|2001",
    "price": 19500
  }
}

PUT /h2h/profile/callback

Mengatur atau memperbarui alamat URL Webhook Callback milik akun Anda secara terprogram (selain melalui form Dashboard → Integrasi H2H).

  • Wajib HTTPS publik: Skema selain https://, URL berisi username/password, hostname internal/localhost, serta IP privat/loopback/link-local akan ditolak (HTTP 400). Maksimal 2048 karakter.
Contoh cURL 
curl -X PUT "https://domain-toko-anda.com/h2h/profile/callback" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: <API_KEY_ANDA>" \
  -d '{
    "callback_url": "https://server-anda.com/webhook/miku"
  }'
Respons 200 OK 
{
  "success": true,
  "message": "Callback URL berhasil diperbarui."
}

9. Verifikasi Webhook Callback (HMAC-SHA256)

Setiap transaksi H2H yang selesai melalui pembaruan callback atau rekonsiliasi sistem pusat akan dikirim ke URL callback Anda via metode POST JSON dengan batas timeout koneksi 5 detik dan tanpa mengikuti HTTP redirect.

  • X-Timestamp: Unix timestamp dalam detik (string) saat payload ditandatangani. Tolak request jika selisih waktu server melebihi ≤ 5 menit (300 detik) untuk mencegah replay attack.
  • X-Signature: HMAC-SHA256 hex lowercase atas string ${X-Timestamp}.${rawBody} memakai Webhook Secret Anda.
  • Raw Body Asli: Hitung signature langsung dari byte body mentah sebelum parsing JSON, lalu bandingkan dengan fungsi constant-time (timingSafeEqual / hash_equals).
  • Respons Endpoint Anda: Proses pembaruan status transaksi secara idempoten berdasar invoice_id dan kembalikan HTTP 2xx (mis. 200 OK) secepat mungkin.
Contoh Payload Webhook (POST ke Server Anda) 
{
  "invoice_id": "H2H-1732450123-AB12",
  "status": "Success",
  "product_name": "86 Diamonds",
  "price": 19500,
  "serial_number": "SN-99887766",
  "timestamp": "2026-11-24T10:15:42.000Z"
}

Contoh Verifikasi Signature

Node.js (Express raw body) 
const crypto = require('crypto');
const express = require('express');
const app = express();

app.post('/webhook/miku', express.raw({ type: 'application/json' }), (req, res) => {
  const timestamp = String(req.header('X-Timestamp') || '');
  const signature = String(req.header('X-Signature') || '').toLowerCase();
  const rawBody = req.body.toString('utf8');
  const secret = process.env.MIKU_WEBHOOK_SECRET || '';

  const tsNum = Number(timestamp);
  const nowSec = Math.floor(Date.now() / 1000);
  if (!Number.isInteger(tsNum) || Math.abs(nowSec - tsNum) > 300) {
    return res.status(401).json({ error: 'Timestamp kedaluwarsa' });
  }

  const expected = crypto
    .createHmac('sha256', secret)
    .update(`${timestamp}.${rawBody}`)
    .digest('hex');

  const sigBuf = Buffer.from(signature, 'utf8');
  const expBuf = Buffer.from(expected, 'utf8');
  if (sigBuf.length !== expBuf.length || !crypto.timingSafeEqual(sigBuf, expBuf)) {
    return res.status(403).json({ error: 'Signature tidak valid' });
  }

  const event = JSON.parse(rawBody);
  // Proses event.invoice_id & event.status secara idempoten di database Anda
  return res.status(200).json({ received: true });
});
PHP (native) 
<?php
$rawBody   = file_get_contents('php://input');
$timestamp = $_SERVER['HTTP_X_TIMESTAMP'] ?? '';
$signature = strtolower($_SERVER['HTTP_X_SIGNATURE'] ?? '');
$secret    = getenv('MIKU_WEBHOOK_SECRET') ?: '';

if (!ctype_digit((string) $timestamp) || abs(time() - (int) $timestamp) > 300) {
    http_response_code(401);
    exit(json_encode(['error' => 'Timestamp kedaluwarsa']));
}

$expected = hash_hmac('sha256', $timestamp . '.' . $rawBody, $secret);
if (!hash_equals($expected, $signature)) {
    http_response_code(403);
    exit(json_encode(['error' => 'Signature tidak valid']));
}

$event = json_decode($rawBody, true);
// Proses $event['invoice_id'] & $event['status'] secara idempoten di database Anda
http_response_code(200);
echo json_encode(['received' => true]);

10. Kode Status & Penanganan Error

Setiap respons error mengembalikan format JSON seragam {"success": false, "message": "..."}.

Status HTTP Arti Penyebab Umum & Tindakan
200 OK Berhasil / Retry Idempotent Permintaan GET/PUT sukses, atau retry POST /h2h/order memakai ref_id dan payload yang sama (mengembalikan hasil transaksi terdahulu).
201 Created Order Dibuat Transaksi baru berhasil masuk antrean atau langsung sukses dan saldo reseller telah terpotong secara atomik.
400 Bad Request Payload / Input Tidak Valid Field wajib kosong, format ref_id tidak valid, saldo tidak cukup, produk tidak aktif, validasi ID gagal, URL callback tidak HTTPS/privat, atau order gagal dikirim ke upstream (saldo aman).
401 Unauthorized API Key Kosong Header X-API-Key tidak disertakan pada request.
403 Forbidden Key Salah / IP Ditolak API Key tidak valid atau telah dicabut, atau IP pengirim tidak terdaftar di Allowed IP reseller.
404 Not Found Tidak Ditemukan Transaksi dengan invoice_id / ref_id terkait tidak ada pada akun Anda.
409 Conflict Konflik Idempotency ref_id sudah pernah dipakai untuk productId atau target akun yang berbeda. Gunakan ref_id baru untuk transaksi berbeda.
429 Too Many Requests Batas Permintaan / Kuota Melebihi rate limit 60 req/menit atau batas transaksi/nominal harian H2H. Terapkan jeda backoff sebelum mencoba ulang.
500 Server Error Gangguan Sistem Pusat Kesalahan tak terduga di server pusat. Lakukan retry aman memakai ref_id yang sama atau cek status via GET /h2h/order/:refOrInvoiceId.
